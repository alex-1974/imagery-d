# Registered mosaic qualification — 2026-11-22

Scope: #148 integration and the registered straight-RGBA8 display slice of
#144, in draft PR #205. This receipt qualifies the declared common-extent
operation, not a release/API freeze, arbitrary warping or 60 fps acceptance.

## Correctness and ownership

The public consumer and independent rational/linear-sRGB Python reference cover
**19 cases / 14,950 pixels**: three independently selected non-power pyramids,
nearest/bilinear/area, reduction and enlargement, missing tiles, signed strides,
spatial quality, validity and alpha. Cases cross both the 256-column and
16-row work-block boundaries. All independently requested partitions and
alternate layouts match byte-for-byte. The independent reference agrees exactly
except adjacent-byte choices at actual half-quantizer boundaries (observed
maximum 1 byte). The gate permits that one-byte choice only within 1e-10 code
units of a half boundary, not for ordinary pixel discrepancies. Validity is exact.

Analytic laws preserve opaque black, separate valid transparency from NoData,
remove hidden-color fringes through linear premultiplication, and produce
188 rather than 128 for an opaque black/white midpoint. Zero-weight bilinear
neighbours do not acquire spurious validity dependencies. Positive missing taps
exclude a source rather than filling holes.

Twenty failure/ownership probes cover result/work budget boundaries, tap/read
limits, invalid ROI/filter/association/quality, inconsistent provider callbacks,
wrong tile shape, provider exceptions, cancellation during work and at the final
publication poll. Prior owners and retained aliases survive failures and a later
successful replacement. A metadata-only 2^30-by-2^30 source supplies a 2-by-2 ROI
with one live provider tile and exactly **four copied pixels**, not a dataset
materialization. The 16-source maximum block consumes **6,029,952 scratch bytes**
with no source reads when quality excludes all contributors. Provider decode
memory, output owners and metadata have separate documented accounting.

Local gates: all six supported compilers in default/no-io (24/23 unittest
modules), DMD 2.111 Debug and LDC 1.43 Release independent consumers, DIP1000
named/scoped positive and nine negative API contracts, and rendered DDOX
including the executable missing-tile example. The existing complete feature
reference suite passes alongside the mosaic consumer on DMD and LDC.

## Throughput method

Host: Linux x86_64, Intel i7-9750H, 12 logical CPUs. DUB release build with
LDC 1.43.0; safe bounds checks retained. Each process is pinned to CPU 0, with
one warm-up and five complete materializations per case. The logs report median,
minimum and maximum. Output RGBA/validity checksumming occurs after the measured
interval and agrees in every case (`908328960` over five iterations).
No other agent builds/reference jobs run during timings. Desktop/VM background
load, frequency, temperature and SMT sibling activity are not controlled. The
before/after series are sequential rather than paired randomized cycles; these
large work-removal effects are local observations, not small-effect statistics.

Each source is one 1536² overview with 256² tiles. The output ROI is 512².
Neutral factors and constant RGBA=(173,173,173,173) exercise color conversion,
premultiplication, weight normalization, ownership, cache and publication, but
not spatial quality/missing/mask branches. One or three source providers are
used. `resident` borrows already prepared tile owners (no decode); `generated`
allocates/fills a test byte array and materializes a fresh planar owner on every
read. These are synthetic provider costs, not codec/HTTP/real-scene timings.
Preparation of resident owners is outside timing; output/scratch allocation,
provider calls/copies and rendering are inside it.

The integer series maps the complete extent to 512²: ratio 3 makes bilinear
centers coincide with exact source centers, so its tap count equals nearest.
The additional fractional series uses a 513-by-517 full target grid and the
same 512² origin ROI, exercising all four bilinear taps and non-integer area
footprints. It is reported separately to avoid treating degenerate bilinear
as representative of general interpolation.

## Removing unnecessary tile copying

The first bounded implementation is preserved at commit
`0f85c663509592249e352356981182a6dbb4667c`. Four cache slots and 256-by-16 work
blocks already avoid whole-dataset residency, but it copies complete provider
tiles on each miss. The follow-up copies only each tile's intersection with
the current source footprint, checks that rectangle on cache hits, and records
actual `copiedPixels`. Sampling mathematics and cache-slot capacity are unchanged.
For integer nearest with one source, 216 provider reads formerly copied
14,155,776 pixels; they now copy 2,255,104. Three sources change 42,467,328 to
6,765,312. Read counts and checksums are unchanged in this series.

these timings do not establish a universal latency improvement.

## Fractional sampling and remaining display gate

| Filter | Resident 1 source ms | Resident 3 sources ms | Generated 1 source ms | Generated 3 sources ms |
|---|---:|---:|---:|---:|
| Nearest | 67.222 | 138.953 | 139.447 | 352.659 |
| Bilinear | 88.472 | 224.408 | 181.356 | 494.779 |
| Area | 163.330 | 467.838 | 261.041 | 761.431 |

Fractional one-source taps are 262,144 / 1,048,576 / 4,153,419 respectively.
Engine work payload is 1,605,672 bytes with one source and 2,195,576 with three;
owned output is 1,310,720 bytes. These exclude provider allocations and metadata.

Even the best measured 512² case is about 15 fps, **below 60 fps / 16.67 ms**.
The candidate therefore does not close #144's display acceptance. Remaining work
includes profiling scalar tap/mix/transfer/store costs, real decoder/cache
integration, viewport/source workloads and a semantically aligned performance
reference where available. SIMD, color quantizer approximations or weaker
NoData/alpha semantics are not inferred from this receipt. The Python numerical
reference is a correctness oracle, not a performance comparator.
