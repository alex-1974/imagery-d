### Workload and pairing

- **Three complete output-producing paths in the same Release executable:** `owned_fused_checked` (private fused 8N control), `owned_extracted_library` (separate 8N producer), and `owned_direct_packed` (new direct 4N producer).
- **40 cases:** two input meaning classes (encoded-straight / linear-premultiplied), two alpha patterns (mixed / transparent), two input layouts (interleaved / planar), and five square ROIs (16, 32, 64, 128, 256), from 512×512 sources.
- **Seven rotating rounds × three stages** per case, **24 complete owned results** per measured stage/round. All output pixels were checked by the runner against its prepared oracle outside timed work.
- Primary ratios and differences are calculated **within each same-numbered round**, then median-reduced across seven rounds per case; group summaries are medians of case medians. Do **not** pool ROI sizes as if their per-pixel weights or total durations were equal.

## Mechanism: one packed owner, no second packing pass

For `N = checked(ROI.width × ROI.height)`, the *requested pixel payload* in the qualified research producer is:

| Path | Peak requested pixel payload | Retained result payload |
|---|---:|---:|
| Private Fused 8N | 8N bytes | 4N bytes |
| Separate extracted 8N | 8N bytes | 4N bytes |
| **Direct-packed 4N** | **4N bytes** | **4N bytes** |

The direct specialized `runPreparedRgbaPixels!(…, SRgba8)` body writes one `SRgba8` directly into a fresh, **unpublished** `RasterLease!SRgba8` target; the second four-byte-channel scratch and post-process packing loop are absent. It reuses the existing `color-d` source-over conversion path and public `raster-d` view/ownership interfaces.

Read-only inspection of the **actual SHA-256-verified benchmark ELF** finds:
- **Four** specialized packed `runPreparedRgbaPixels` instances (PM combinations 00/01/10/11).
- **Zero explicit calls** to `RasterView.trySample` / `WritableRasterView.trySetSample` in each packed direct kernel and in `tryCompositeOwnedRgbaDirectResearch` itself.
- In the old `tryCompositeOwnedRgbaResearch` packing region, **four `RasterView!ubyte.trySample` calls plus one `WritableRasterView!SRgba8.trySetSample` call** remain.

The x86-64 PIE ELF is unstripped, **1,734,576 bytes** total with **692,352 bytes** in `.text`. This call-site difference supports the proposed mechanism but does not by itself prove all performance causality. The paired measurements establish the performance result.

The **4N/8N comparison is about requested image pixel payload**, **not** process RSS, native allocator bookkeeping, input owners, metadata allocations, GC pauses, actual system memory reservations, or exact global cache retention accounting. Likewise zero recorded *thread-local* GC bytes does not prove zero native allocations or a whole-function `@nogc` guarantee.

## Correctness and failure scope

The exact measured research commit passed five GitHub workflows according to its separately verified exact-head CI record. Its independently compiled small DUB consumer includes direct-packer parity over all four PM masks × mixed/transparent patterns, source owner independence and retention, preflight rejection, nonempty `ref RasterLease` preservation, and actual native allocation/import fault witnesses (direct kinds **2/3/4**; the old 8N research path also retains its original tests). The XPS run independently validates the archived receipts, checksum consistency and process results, **not** by rerunning foreign ELF or proving an independent full numerical oracle from the CSV alone.

Do **not** extend those facts to:
- arbitrary druntime `Error`-level out-of-memory recovery;
- atomic snapshots under concurrent source mutation or thread-safe lease copying;
- arbitrary foreign caller-owned destination alias safety;
- exact retained physical-byte refund after freely copied external raster leases;
- other hardware, compilers or non-synthetic production pipelines.

## Research decision and promotion stops

**ACCEPT the direct-packed 4N algorithm as the current preferred M3 research producer.** It removes the formerly measured 8N extraction regression without requiring ThinLTO as a performance rescue and halves the producer's modeled **requested output pixel-payload peak**. Retain the previously measured 8N and ThinLTO controls as negative/positive comparative evidence; comparisons against those **separate old archives are unpaired**, not same-run causal A/B experiments.

**Still blocked:** Design #75 requires a **named, genuine non-test downstream caller** whose requirements justify independent owned output. The independently built DUB test consumer is an integration gate, not that product-use proof. B remains a **conditional result-form preference**, not an admitted public name/signature. Research #74 independently owns any request for exact arbitrary-subscriber/cache physical accounting.

Before a production ADR: establish concrete downstream consumption; select the narrowest appropriate result transport and failure types; ensure the full native fault/owner/PM matrix survives the **actual minimal package**; add public Ddoc, positive/negative compile contracts and supported DMD/LDC gates; and remeasure the production artifact/end-to-end consumer where applicable.

**No edits to `source/imagery`; no promotion to `develop`, `main`, or `research-integration`; do not rebase, retarget or merge Draft PR #73.**
